# 切片 12：填写跑步数据

日期：2026-09-26。

范围：为跑步记录提供时长（分钟）、距离（公里）、心率（次/分钟）的手动可选输入，仅在本次运行内临时保留。

## 修改

- `miniprogram/pages/record/index.js`：按计划 ID 读取当前完成结果中的 `result.runningData`，三个字段为 `durationMinutes`、`distanceKm`、`heartRate`。使用字符串草稿保留空白与用户输入的零；允许非负有限十进制数，确认时再次校验，拒绝负数、非数字、混合文本及非有限值。
- 首次“确认按计划完成”可一并记下跑步数据；已完成后可通过“确认跑步数据”补填、修改或清空。未确认离页不写入，重进回显已确认内容。补填前检查计划有效、仍为跑步、当前结果仍为原完成结果；仅修改跑步数据，不覆盖心情、体感、结果状态或其他计划。
- `index.wxml`、`index.wxss`：增加带单位的三项输入、错误提示、确认按钮和临时状态说明。只有跑步且未进入未完成/修正表单时显示；其他运动不展示跑步字段。
- 与并行第 11 片的体感接入兼容：选择体感成功后只更新体感显示，避免刷新整页时清掉未确认的跑步草稿；失效目标仍刷新保护。
- 新增 `tests/record-running-data.test.js`、本验证记录及三张模拟器截图；追加 `PRODUCT.md` 本片能力说明。

本任务未实现配速计算、GPS、计时器、手表同步、持久化或其他后续功能；没有修改今天页、周计划或 App。开始前已有未提交修改保留。

## 模拟器取证

在原项目空运行中注入 3 条明确的临时验收安排：19:00 跑步、07:00 跑步、08:00 瑜伽；未注入完成结果或跑步数据。19:00 跑步带一段用于隔离断言的运动前测试备注。

- 实际输入 `30.5 / 5.25 / 145` 并点击完成，返回再进入，三项正确回显。
- 距离分别输入 `-1`、`abc`，检查错误提示和禁用按钮，已确认值仍为 `5.25`。
- 改回合法距离，将心率草稿改为 `150`，选择“适中”体感后再确认；心率草稿未丢失，体感与运动前感受均保留。再次进入回显 `150` 与“适中”。
- 07:00 跑步全空确认仍为已完成；仅距离输入 `0` 后重进，其他两项仍空且 19:00 跑步不变。清空后再次确认、重进三项均空。CLI 不接受空 `--value`，清空使用元素 `input` 事件传入空字符串。
- 瑜伽完成前后都没有跑步表单，结果中没有跑步数据字段。
- 验收结束仅移除本轮 3 条临时安排，回到今天页空状态。
