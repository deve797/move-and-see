# 切片 2：修改一条未来安排

日期：2026-09-26。范围依据根目录 `切片.md` 的切片 2。

## 实现范围

- 用户添加的未来、无结果安排显示“修改安排”，复用新增表单并回填日期、项目和时间。
- 草稿独立；确认后更新原安排，保留 ID 和条数；放弃编辑不改变原内容。
- 修改日期后从旧日期移除、显示在新日期；跨周时显示目标周。
- 开始时间按北京时间（UTC+8）判断，等于或早于当前时间不可编辑；新时间也必须在未来。确认时重新检查原安排，防止表单打开期间开始或出现结果后仍能修改。
- 当前没有结果录入功能。已有结果的保护使用 `plan.result` 判断，仅在测试中注入结果样例验证，没有提前实现结果功能。
- 保留固定示例与临时安排标识，仍只使用当前页面内存。

不实现取消安排、批量调整、重复排班、修改历史结果、持久化或其他切片。

## 分步验证

1. 改动前运行切片 1 测试，通过。
2. 编辑逻辑完成后运行 JS 语法检查、切片 2 自动化验收、切片 1 回归，通过。
3. 接入 WXML 编辑入口及复用表单后，再次检查语法及两组测试，通过。
4. 微信开发者工具编译周计划页，操作入口、确认及放弃按钮；核对运行时数据、入口数量和截图。

| 验收项 | Node 页面逻辑测试 | 微信模拟器 |
| --- | --- | --- |
| 周二改周三，旧日期移除、新日期出现 | 通过，保留同日另一条安排 | 通过，9/29 跑步改为 9/30 网球 |
| 修改项目、时间仍只有原安排 | 通过，ID、总数及其他安排不变，重复确认不新增 | 通过，19:00 跑步改为 18:30 网球，ID=1、总数=1 |

| 已开始或已有结果不能编辑 | 通过，含等于开始时刻、直接调用、编辑期间到时/新增结果 | 注入临时样例检查：过去安排及已有结果安排均无编辑按钮 |

额外自动化覆盖：缺失项目或时间、新时间在过去/等于现在、跨周跨年修改、切周后返回、无效 ID。
