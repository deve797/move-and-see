# 个人资料与“我的”页面

2026-09-30。

## 范围与数据

- 沿用每次微信调用的 OPENID 身份，不新增账号密码、手机号或独立登录流程。
- “我的”页面展示默认头像和昵称，支持编辑昵称、自选头像、保存和取消。首页与今天页提供入口。
- `profiles` 集合保存 `nickname`、`avatarFileID`、`version`、时间戳、`_owner` 和 `_kind`。昵称为去掉首尾空格后的 1–20 个 Unicode 字符；首次读取未设置资料时返回空值和版本 0，不自动写入。
- 每人一个以 OPENID 哈希生成 ID 的资料文档，请求回执也按调用者隔离。客户端不能提交 owner、文档 ID、头像 URL 或 fileID 作为写入目标。
- 头像仅允许 JPG、PNG、WebP，最多 512 KiB。客户端读为 base64，通过已鉴权的 `moveSeeApi` 上传；云函数生成 `avatars/<owner hash>/<image hash>.<ext>`，资料中只存 fileID，读取时换取 600 秒有效的临时链接。
- 昵称与头像引用在同一事务中保存，包含乐观版本和幂等回执。失败保留草稿；响应丢失时重复提交可读回已保存版本。临时链接获取失败不把已成功保存的资料误报为失败。
- 头像文件使用不可变内容路径；更换头像或写入结果不确定时保留旧文件，避免删除已提交资料仍引用的文件。本版不提供头像历史或后台文件清理功能。

## 必需云端资源

环境：`xiangqiandong-d9g120h8m6a8ed8da`；小程序：`wx2c23ae79d174802d`。

1. 创建 `profiles` 集合，并设置 `ADMINONLY`（客户端读写均拒绝）。
2. `avatars/` 文件路径必须对客户端读写均拒绝。若云存储没有其他业务文件，可设置整个存储为 `ADMINONLY`；有其他用途时，读取现有规则，仅限制头像路径。
3. 更新事件云函数 `moveSeeApi` 代码，沿用 Nodejs18.15、原有环境变量和身份校验。
4. 配置后读回规则，并从小程序客户端确认直接读取 `profiles` 被拒绝，再启用实际资料保存。

头像权限独立于数据库权限，不能仅靠资料表的归属字段保护文件。临时签名链接作为访问凭据，不写入项目或长期存储，不放入分享参数。官方接口依据：[云存储 SDK](https://docs.cloudbase.net/api-reference/server/node-sdk/storage)、[安全规则](https://docs.cloudbase.net/storage/security-rules)。同时检查了项目固定版本 `wx-server-sdk@3.0.1` 的上传和签名接口参数。
