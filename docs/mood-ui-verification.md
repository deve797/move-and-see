## 验证结果

微信开发者工具原生模拟器，基础库 3.17.3；运行时读取逻辑视口及元素边界，并查看两种宽度的顶部、底部截图。

| 检查 | 结果 |
| --- | --- |
| 320px，内容视口高 504px | 选项左右边界 20–300px，每行高 88px；备注区域高 144px，返回按钮高 44px；无横向溢出，滚动后底部完整可见 |
| 375px，内容视口高 603px | 选项左右边界 24–351px，每行高 96px；备注区域高 148px，返回按钮高 44px；无明显溢出或遮挡 |
| 单选交互 | 实际点击圆点选择“差不多”，点击文字选择“更差”；整行可选，始终只保留一项选中 |
| 备注输入 | 自动化输入 10 字样例正常；通过真实界面粘贴 210 个中文字符，实际保留 200 字，显示 `200/200`，焦点态正常 |
| 记录页往返 | 从“40 分钟 / 跑步”进入心情页，再返回仍显示原运动与时长 |
| 独立入口与重新进入 | 独立打开后返回记录页，显示“32 分钟 / 户外行走”；重新进入心情页恢复“更好”和空备注 |
| 代码交互检查 | 首轮 33 项 Node VM 断言通过；修正后的 13 项相关断言通过 |
| 现有运动动画 | `node tests/exercise-motion.test.js` 通过 |
| 静态与运行时检查 | JS 语法、`git diff --check` 通过；最终控制台 `error` 检索为空 |

首次检查发现选项标签默认盒模型造成额外高度、部分灰字对比度约 4.29，以及标签点击未可靠触发选择。一次修正加入明确的 `border-box`、将相应灰字调整为 `#686d65`（对比度约 4.80），并同时支持整行点击和原生单选变化；复核确认三项问题已解决。CLI 合成标签点击未产生预期事件，因此整行交互结论依据实际界面点击验证。

仅完成模拟器验证，未做真机键盘或底部安全区验证。备注已配置原生键盘避让与光标间距；未上传或发布。

## 相对概念图的主动调整

1. 使用微信原生导航、返回、胶囊及单选控件的选中符号，保持原有标题、三项选择、备注的层级顺序。
2. 表情采用可编辑 WXML/WXSS 几何图形，保留笑脸、平静脸、低落脸的区分；本页不使用位图文字或新增图片。
3. 将整行作为选择目标，保留文字说明和单选符号共同表达状态；提高灰字对比度，便于阅读。
4. 320px 短屏自然纵向滚动，适当缩小间距，保留可读文字和至少 44px 的操作高度。
5. 备注使用原生多行输入、200 字限制与实时计数；下方保留低强调的返回入口和“不保存”提示，符合本轮仅前端演示的范围。
